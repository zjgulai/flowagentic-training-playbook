    对话流程 Chatflow¶

    目标¶

    从空画布建立最小问答流程，完成节点配置、连接、保存、测试、执行检查和安全发布前验证。

    先理解画布¶

    一个可运行的 Chatflow 至少需要明确输入怎样进入、模型或链怎样处理、结果怎样返回。节点之间的连线表达数据依赖；画布位置只是视觉布局，不改变执行语义。

    最小 Chatflow SOP¶

    前置条件¶

    • 只在隔离培训环境操作。
    • 已创建受控 Provider 凭据，预算 ledger 正常。
    • 使用合成问题，不上传真实文档。
    • 约定流程名称、所有者、清理时间和对象 ledger。

    1. 新建并命名¶

    进入对话流程列表，确认搜索和工作空间筛选。新建空白流程，名称使用“培训—企业 FAQ—学员编号”，避免覆盖讲师基线对象。

    检查点：新对象 ID 已写入实验 ledger。

    2. 添加并配置节点¶

    从节点面板添加最小输入／提示与模型处理节点。选择培训 Provider 凭据，设置低风险模型参数；不要在提示词中粘贴 Key。

    检查点：所有必填参数有值；凭据字段只显示引用；模型和端点与培训预算一致。

    3. 连接与验证¶

    按端口类型连接节点。执行画布验证，逐项处理缺失输入、类型不匹配和孤立节点。

    检查点：没有未连接的业务节点；输入输出类型能解释；验证通过不代表 Provider 一定可用。

    4. 保存¶

    保存后观察未保存提示是否消失。刷新页面并重新打开，确认节点、连线和配置仍存在。

    检查点：刷新后的状态与保存前一致；对象更新时间合理。

    5. 聊天测试¶

    使用合成问题运行一次。等待完成后核对答案、来源、工具结果和执行记录；不要为“看起来卡住”而连续点击发送。

    检查点：执行记录中的流程 ID、Session、模型、token、延迟与本次测试匹配。

    6. 失败与回退¶

    • 参数错误：回到对应节点修正并重新验证。
    • Provider 401/403：检查凭据引用和 Provider 权限，不把 Key 输出到日志。
    • 429/超时：停止密集重试，采用有上限的指数退避。
    • 输出不可信：检查提示、输入和来源；不要只调高随机性。
    • 保存错误：保留当前页面，不创建同名副本；先判断服务端是否已写入。

    7. 清理¶

    实验结束后按 ledger 删除学员对象，并检查执行、API Key、临时凭据和外部资源是否残留。共享基线对象只读，不删除。

    发布前检查¶

    • 流程名称、说明和状态清晰。
    • 导出 JSON 不含秘密和内部 URL。
    • API、SSE、Embed 和公开聊天分别完成授权、CORS/CSP、限流和数据边界验证。
    • 已测试成功、空输入、Provider 失败、超时和恶意输入。
    • 有明确回滚版本或可验证的导入制品。

    导入、导出、复制和模板¶

    导入前检查来源、版本、节点依赖和凭据占位符；导出后做秘密扫描。复制流程会产生新对象，应重新核对 API Key、文档库和变量引用。模板只能作为起点，不继承原作者环境的可用性保证。

    截图证据¶

    正式版本将覆盖列表、空画布、节点面板、配置、连线、保存、聊天测试、来源、失败和执行记录等关键状态。当前 G1 未通过，因此 screenshot_ids 为空，不展示未经版本绑定的旧图。

    适用角色¶

    新手按最小流程练习；流程搭建者负责节点和发布配置；开发者负责 API／Embed 边界；管理员负责凭据、费用和删除授权。

    适用版本与功能状态¶

    本 SOP 绑定 Flowise 3.1.3 与提交 96f6ae46…，Chatflow 为 production-enabled。最终界面、截图和运行结果等待该精确提交的同版本隔离环境复验。

    前置条件与风险¶

    需要隔离培训环境、合成问题、受控模型凭据、对象 ledger 和费用余量。模型调用会产生费用，Tool／HTTP 节点还可能产生外部写入。

    初始状态¶

    从对话流程列表进入，确认无同名实验对象、当前工作空间正确、搜索筛选已清空，基线对象保持只读。

    操作步骤¶

    按“新建命名 → 添加节点 → 配置凭据 → 连线验证 → 保存重开 → 聊天测试 → 执行核对 → 发布前检查”的顺序执行本页最小 Chatflow SOP。

    逐步检查点¶

    每一步都记录对象 ID、保存状态和执行 ID；Provider 调用前检查预算，外部写入前检查幂等键，刷新后确认画布与保存前一致。

    成功结果¶

    流程可从列表重开，以合成输入完成一次受控响应，执行记录中的流程、Session、模型、token、费用和结果与本次操作一致。

    常见错误与诊断¶

    验证失败先检查必填参数和端口类型；401/403 检查凭据引用；429/超时停止密集重试；保存异常先确认服务端是否已写入，避免重复创建。

    回退与清理¶

    恢复上一已验证导入制品或删除本次实验对象；按 ledger 清理执行、临时凭据、API Key 和外部资源，不删除共享基线。

    安全提示¶

    导出 JSON、提示、日志和截图不得包含 Key、Cookie、内部 URL、真实数据或资源标识。公开聊天、API、SSE 与 Embed 需分别验收认证、限流、CORS/CSP 和数据最小化。

    练习任务¶

    建立“企业 FAQ”最小流程，完成一次成功问答、一次空输入拒绝和一次 Provider 模拟失败，再恢复到成功状态。

    验收清单¶

    • 保存重开后节点、连线和配置不变。
    • 成功、失败、恢复三条路径可由执行记录追溯。
    • 费用和秘密扫描通过，实验对象已清理。

    来源与验证¶

    页面引用的 Claim 覆盖流式验收、截图版本、session 和副作用。正式发布要求这些 Claim 达到三角验证且截图绑定同一新 SHA。
