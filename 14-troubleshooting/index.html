    故障排查¶

    通用方法¶

    先保留证据，再缩小范围；先找第一处异常，再处理最终症状。每次只改变一个变量，并记录“假设—操作—结果”。

    1. 记录时间、用户可见症状、目标环境、页面或流程、Session 和触发方式。
    2. 判断影响范围：单用户、单流程、单 Provider，还是全站。
    3. 检查最近变更：发布、凭据轮换、节点配置、文档 Upsert、网络或功能开关。
    4. 在执行记录定位第一个异常节点。
    5. 在浏览器网络面板和控制台定位请求；公开材料只保留脱敏摘要。
    6. 用合成输入做最小复现，不在生产重复高风险操作。
    7. 修复后同时验证正常、失败和恢复路径。

    症状入口¶

    无法登录、401、403、429¶

    • 401：先检查会话、Cookie、系统时间和账号状态。
    • 403：检查权限、工作空间和功能开关，不重复登录绕过。
    • 429：停止密集尝试，确认限流窗口与请求来源。

    节点面板为空¶

    检查搜索、类别筛选、节点加载接口、浏览器控制台、服务端节点池初始化和构建制品。不要通过创建重复流程验证。

    凭据无法解密¶

    停止轮换和删除。检查加密密钥连续性、数据卷与部署变更；不要把密文、Key 或环境变量复制到公开渠道。

    变量没有生效¶

    核对变量名称、作用域、保存状态、$vars 引用与请求级覆盖允许列表。执行记录中的实际输入比画布显示更接近事实。

    Provider 超时或限流¶

    区分 DNS／TLS、认证、连接、Provider 限流和模型处理超时。检查有上限退避，不允许无限重试。

    Streaming 不工作¶

    验证普通请求是否成功，再检查响应头、代理缓冲、CORS/CSP、连接中断和客户端事件处理。

    RAG 为空、Stale 或维度错误¶

    按“载入 → 切分 → Embedding → Upsert → 集合 → 检索”逐层检查，参见文档库章节。

    MCP 授权或工具发现失败¶

    检查 URL、协议、证书、认证、Token 范围、服务端能力和网络边界。不要在 URL 或日志中暴露 Token。

    HITL 无法恢复¶

    确认原执行是 STOPPED、Session 和流程版本匹配、操作者有权限，并检查待审批载荷是否完整。

    Schedule／Webhook 不触发¶

    检查功能开关、注册状态、时区、签名、网络、重复投递和服务端日志。手工运行成功不能证明触发器正常。

    上传失败¶

    检查文件类型、大小、数量、编码、存储权限和恶意内容防护。不要用真实敏感文件试错。

    何时停止¶

    出现秘密泄露、真实数据进入错误环境、未知外部写入、费用快速上升、疑似无限循环、加密密钥异常或证据将被覆盖时立即停止，并升级给相应所有者。
