# 版本差异与内容适用边界

当前逻辑稿绑定 Flowise `3.1.3` 与目标提交 `96f6ae464f7f4757883a5ba6bec26ca951b4da4d`。该提交已经合并到远端 `main`，并完成本地全量验证、独立提交级复核、主分支自动 CI 和人工离线制品 readiness；这些证据证明源码与离线镜像候选的精确身份，不证明生产已经切换或完成浏览器验收。正式截图版本必须给出实际部署的 40 位 SHA、版本号、部署时间和与本基线的差异清单；只要部署 SHA 不同，所有页面、节点参数和截图引用都必须重新做差异复核。

## 目标定制与上游 3.1.3

目标提交已经包含中文侧栏、十个主模块、管理员登录路径和关闭注册的路由行为。上游 3.1.3 Release 同时包含 Agentflow 变更、将 Chatflow 暴露为 MCP Server、流程配置界面重设计和安全修复。Playbook 对这些能力采用三种状态：

| 状态 | 含义 | 对正文的约束 |
|---|---|---|
| `production-enabled` | 目标源码存在且目标部署已验收 | 可进入主 SOP，但仍需新 SHA 截图 |
| `feature-gated` | 源码或上游存在，受开关、权限或许可证控制 | 放入扩展附录，写明开启条件 |
| `experimental` | 包或接口明确处于 Dev/实验状态 | 不承诺稳定性，提供版本锁定和回退 |

Agentflow V2 主功能可以进入使用教程，但 `@flowiseai/agentflow` 可嵌入包在目标提交的 README 中仍声明为 Dev。两者不能在课程中混为同一个稳定性承诺。

## 目标候选的 G1-K 加固

`96f6ae46…` 在原定制基线上加入了几项直接影响培训操作的边界：

- 工作区导出采用依赖闭包；凭据引用、变量值、MCP 连接和 Provider／HTTP 敏感选项不会作为可恢复绑定进入公开导出。
- 工作区导入不信任 manifest，在生成新 ID 和写入前清洗秘密与跨工作区引用；导入后必须由管理员重新绑定凭据、变量、MCP 和公开访问策略。
- 发现旧版 MCP 明文 Token 时迁移会禁用配置并删除旧 Token／摘要；管理员重新启用后领取一次性显示的新 Token，旧客户端在此之前有意中断。
- MCP 公共命名空间采用路由内有界 JSON 解析、固定未知路由响应和低基数脱敏审计；审计不记录流程 ID、原始路径、Header、query、body、Token 或错误正文。
- 旧版 Provider-backed OpenAI Assistant／Vector Store 的读取和非破坏性更新同时要求业务权限与 `credentials:view`；Provider 畸形分页固定失败，不伪装为空列表。

这些合同已有源码、测试和静态安全证据，同版本隔离环境也已完成全新数据库迁移与基础认证；角色矩阵、旧客户端和专项运行审计仍未复现。它们不能被解释为生产部署已完成；旧 MCP 客户端中断和重新发 Token 还必须进入变更窗口计划。

## 上游 3.1.4 漂移

3.1.4 于 2026-07-29 发布，晚于本 Playbook 的目标上游版本。发布记录包含以下与公开培训直接相关的变化：

- Custom MCP stdio 命令 allowlist 改为由运维方控制；
- OpenAI Realtime 的跨工作空间授权修复；
- 导出内容可能包含变量值的修复；
- Web Scraper deny-list 检查增强；
- 租户校验、组织用户清理、SSO/Role 等安全修复；
- Node load method 的 workspace 边界修复。

这些条目说明 3.1.3 与 3.1.4 之间存在实质安全差异，但不能仅凭 Release 判断目标提交是否已回移某项修复。升级建议必须先完成 commit-by-commit 对照、目标补丁盘点和隔离回归。

### 可筛选差异矩阵

| 差异项 | 目标基线 | 上游参照 | 目标回移状态 | 风险 | 本地／培训验证状态 |
|---|---|---|---|---|---|
| Custom MCP stdio 命令 allowlist | `96f6ae46…` / 3.1.3 | 3.1.4 | 未确认 | 任意命令与运维策略漂移 | 目标目录已定位；隔离复现阻断 |
| OpenAI Realtime 跨工作空间授权 | `96f6ae46…` / 3.1.3 | 3.1.4 | 未确认 | 跨租户访问 | 未进入主课程；安全对照待做 |
| 导出变量值修复 | `96f6ae46…` / 3.1.3 | 3.1.4 | 目标定制已实施同类清洗，未声明与上游补丁同源 | 导出物泄密 | 源码与测试通过；隔离导出／导入复现阻断 |
| Web Scraper deny-list | `96f6ae46…` / 3.1.3 | 3.1.4 | 未确认 | SSRF／内网访问 | 只登记差异；未宣称目标受影响 |
| 租户、组织、SSO、Role 修复 | `96f6ae46…` / 3.1.3 | 3.1.4 | 目标定制包含工作区导入／导出与权限加固；其余项未确认 | 权限提升／清理遗漏 | 相关测试通过；逐角色复现阻断 |
| Node load workspace 边界 | `96f6ae46…` / 3.1.3 | 3.1.4 | 目标定制包含动态子配置清洗；未证明与上游补丁等价 | 跨工作空间节点加载 | 311 节点静态目录通过；运行边界待验证 |

“未确认”是明确的发布状态，不等于目标版本存在漏洞；“同类清洗”也不等于目标分支包含相同上游提交。正式发布前，维护者必须把每行更新为“已包含／已回移／不适用／仍缺失”，并附目标 commit、测试和隔离运行回执。

## 中文候选 G1 运行门禁

当前精确候选还必须同时满足：

1. 提供实际部署的精确 SHA、产品版本、镜像摘要和部署时间；
2. 十个主页面与弹窗完成 PC 端验收；
3. 除白名单术语外，不再出现未解释的英文主文案；
4. 术语、日期、按钮动词、错误提示和危险操作文案一致；
5. 关键路由和浏览器控制台检查通过；
6. 证明部署 SHA 与 `96f6ae46…` 一致；若不一致，给出完整功能与安全差异。

在 G1 通过前，研究、正文和截图脚本可以迭代，但正式截图、Provider 实验结论、mike 版本发布与 `latest` 更新保持关闭。

## 维护规则

每次新版本都要更新 Claim 的 `last_verified` 与 `evidence_status`，重新生成节点目录，重跑内部链接和外链检查，并只替换与差异相关的截图。旧版本通过 mike 保留，避免把新版步骤覆盖到旧版读者的运行环境。
