# 管理员与公开安全运维

## 公开内容边界

本章只说明可公开的原则、门禁和检查表。真实域名、IP、拓扑、主机、数据卷、部署密钥、备份位置、恢复命令和回执属于私有 Runbook；公开站仅显示受控参考编号。

## 功能开关与权限

功能在代码中存在、路由可达、导航可见、当前角色有权和生产可用是五件事。变更开关或权限前记录现状、影响用户、回退值和验收路线。前端隐藏不能替代服务端授权。

## 加密密钥与数据连续性

Credential 解密依赖加密密钥和持久化数据的连续性。备份必须包含一致的应用数据、配置和密钥材料，并在隔离环境做恢复演练。禁止把密钥写进公开仓库、日志、截图或工单。

## 日志与审计

- 记录时间、身份、动作、对象、结果和关联请求标识。
- 默认不记录秘密、完整提示、真实文件和不必要个人数据。
- 日志保留期限、访问权限和删除策略明确。
- 分享执行或日志前做脱敏和最小化。

## 工作区导入与导出

导出文件是待审查的数据制品，不是“天然安全的备份”。目标候选使用依赖闭包避免生成无法恢复的半截对象，并移除凭据引用、变量值、MCP 连接以及 Provider／HTTP 敏感配置；自由文本、自定义代码、聊天、文档和错误仍可能携带敏感信息，公开前必须另做人工审查和扫描。

导入端不把 manifest 当授权。所有对象在写入前重新生成 ID、按服务端 allowlist 取字段、清洗秘密和跨工作区引用，并以事务写入。`workspace:import` 可以引入流程、模板和 Custom Tool 代码，属于高信任权限；导入完成后由管理员逐项重新绑定凭据、变量、MCP 和公开访问策略。

## 发布检查表

1. 固定候选 SHA、镜像摘要、迁移与配置差异。
2. 在隔离环境完成构建、测试、迁移和十个主模块 PC 验收。
3. 检查备份可恢复、回滚制品可用和负责人就绪。
4. 生产变更获得明确授权并限定窗口。
5. 发布后检查健康、登录、关键路由、控制台和只读主链。
6. 记录部署时间、结果和异常；观察完成前不宣称闭环。

## 回滚原则

回滚触发条件在发布前定义。回滚不仅是代码，还要考虑数据库迁移、配置、密钥和外部副作用。任何不可逆迁移必须有前向修复方案和隔离演练。

## 备份与恢复

公开检查表只确认“覆盖范围、加密、保留、完整性、恢复演练和回执”。具体命令保留在私有 Runbook。备份文件存在不等于可恢复；必须以隔离恢复结果作为证据。

## 安全升级

持续跟踪上游 Release、安全通告和依赖风险。升级前做本地差异审计；升级后重新生成节点目录、功能矩阵、研究结论和截图，不能沿用旧 SHA 的证据。
