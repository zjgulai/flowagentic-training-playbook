# 实践卡片：优化建议与关键 Tips

本页只收录可复现实验或有明确来源锚点的建议。标记为“经验建议”的内容不是 Flowise 官方规则；在正式培训中，学员要先在合成数据环境完成实验，再决定是否应用到自己的流程。

## 卡片 1：把流程输入合同写在 Start 节点

**证据状态：研究建议（发布阻断）。** `CLM-018` 当前尚未完成目标版本培训环境复现。

**问题和适用条件。** Chat、Form、Webhook 和 Schedule 的请求形态不同。如果后续节点直接猜测字段是否存在，同一画布在四种触发器下会产生不同结果。

**证据与版本。** 官方 Agentflow V2 文档定义多种 Start 输入；维护者在 3.1.3 周期修改过 Form 选项过滤；开发者报告过 Form Input 的 Embed 请求缺少 `question`。[CLM-018]

**推荐做法。** 在 Start 中显式声明必填字段、默认值和 Flow State 键。为每种启用的触发器保存一条合成请求 fixture，并分别验证请求体、节点输入、结构化输出和错误提示。

**不适用情况。** 只有单一、固定的内部调用方时，可以减少触发器组合，但仍要保留请求 Schema。

**成本和风险。** 成本低；主要风险是把 UI 默认值误当作 API 默认值。

**复现实验。** 使用相同工单数据分别从 Chat 与 Form 调用，比较 Start 节点输入、执行记录和最终结构化输出。任何缺失字段都应在 Start 或首个校验节点失败，而不是在 Provider 调用后失败。

## 卡片 2：Flow State 只保存流程需要共享的最小状态

**证据状态：研究建议（发布阻断）。** `CLM-006` 当前为部分证据，隔离 session 对照仍被外部门禁阻断。

**问题和适用条件。** 把完整模型响应、文档块或凭据相关数据写入 Flow State，会增加上下文体积、调试噪声和泄露面。

**证据与版本。** 官方文档把 Flow State 定义为一次执行内的共享状态，并要求先在 Start 声明键；目标 Agentflow 包包含状态编辑和变量选择能力。[CLM-006]

**推荐做法。** 只保留稳定、可命名的业务字段，例如 `ticket_id`、`intent`、`approval_status`。大型检索结果通过节点输出传递，敏感值只保留引用，不写入提示词、截图或分享执行记录。

**不适用情况。** 需要跨执行持久化时，应使用明确的数据库、记忆或业务 API，而不是假设 Flow State 会自动保留。

**成本和风险。** 状态设计需要额外建模，但能减少 token、序列化和排障成本。

**复现实验。** 构造两个并发 session，分别写入不同工单号，确认状态不串线；再发起第二次执行，确认未声明持久化的数据不会被错误复用。

## 卡片 3：变量覆盖必须可追溯

**证据状态：经验建议（发布阻断）。** `CLM-008` 当前为 proposed，覆盖优先级控制实验尚未执行。

**问题和适用条件。** 同名静态变量、Runtime 变量和 `overrideConfig` 容易造成“页面显示正确、执行使用另一个值”的错觉。

**证据与版本。** 目标提交有变量服务和端到端测试；官方文档分别说明 Variables 与 Prediction API。[CLM-008]

**推荐做法。** 为变量建立所有者、用途、默认值和允许覆盖来源。实验中记录静态值、请求覆盖值、节点最终输入和执行结果，但对密钥只记录指纹或是否存在。

**不适用情况。** 凭据不能用普通变量管理，也不应为了方便调试而把 Token 复制到执行日志。

**成本和风险。** 主要风险是环境漂移和误覆盖；治理成本来自命名和轮换。

**复现实验。** 用同名合成变量依次执行“无覆盖、请求覆盖、空值覆盖、非法类型”四组请求，确认优先级和错误路径。

## 卡片 4：Streaming 验收看完整事件协议

**证据状态：经验建议（发布阻断）。** `CLM-009` 当前为 proposed，目标版本流式故障注入尚未执行。

**问题和适用条件。** 首个 token 出现并不代表流式链路完整；网络中断、缺失 end、错误事件被吞或空内容都会让客户端卡住。

**证据与版本。** 官方 Streaming 与 Prediction API 给出流式语义，开发者报告过 Prediction SSE 偶发无内容。[CLM-009]

**推荐做法。** 客户端状态机至少覆盖连接、metadata、token、end、error、cancel 和 timeout。日志记录事件类型、顺序、时延和大小，不记录敏感正文。

**不适用情况。** 明确使用非流式、短响应的后台任务不需要 SSE 状态机，但仍要有超时和错误处理。

**成本和风险。** 增加客户端测试和可观察性；收益是避免“模型已完成但 UI 仍加载”的模糊故障。

**复现实验。** 在代理层主动中断连接、延迟末尾事件、返回空 token，并确认 UI 能结束加载、显示可操作错误且不会重复提交。

## 卡片 5：把浏览器网络流当作公开接口

**证据状态：风险假设（发布阻断）。** `CLM-010` 当前为 proposed，目标版本抓包与 canary 扫描尚未执行。

**问题和适用条件。** Embed 或公开聊天中，用户可以查看浏览器请求和 SSE 事件。未显示在界面上的字段也可能已经发送到终端。

**证据与版本。** 开发者报告过 Agentflow 内部事件可从 SSE 网络流观察；该现象尚未在目标版本复现，因此属于风险假设。[CLM-010]

**推荐做法。** 以不受信任客户端视角抓包，检查 prompt、工具参数、文档 metadata、内部错误、资源 ID 和节点输出。服务端只发送客户端真正需要的字段，并通过合成敏感标记自动扫描。

**不适用情况。** 纯服务端调用不会暴露浏览器流，但响应、日志和下游 API 仍需相同的数据最小化审计。

**成本和风险。** 抓包和字段白名单需要维护；风险是业务数据、系统提示或内部路径泄露。

**复现实验。** 在合成文档中植入唯一 canary 字符串，运行 Embed 对话并搜索浏览器网络导出；任何非预期出现都阻断发布。

## 卡片 6：MCP 网络策略采用 fail-closed 白名单

**证据状态：研究建议（发布阻断）。** `CLM-012` 当前为 partial，目标 3.1.3 配置与补丁回移状态尚未复核。

**问题和适用条件。** Custom MCP 可能连接本地进程、容器服务或远程 HTTP 服务。过宽网络访问会形成 SSRF 和内网探测风险，过严策略又可能阻断合法容器拓扑。

**证据与版本。** 目标源码包含 Custom MCP 和安全测试；开发者报告过 Docker 内部主机名被策略阻断；3.1.4 又将 stdio 命令 allowlist 调整为运维方控制。[CLM-012]

**推荐做法。** 保持安全检查开启，由运维方按精确协议、主机、端口和命令建立白名单。培训只使用隔离 MCP 服务和合成工单，不把生产内网加入示例。

**不适用情况。** 不需要 MCP 的流程应完全不配置该连接；不要为了绕过一次错误全局关闭安全检查。

**成本和风险。** 白名单增加变更审批，但能让可达范围可审计。错误配置可能造成服务不可用或访问越权。

**复现实验。** 依次测试允许目标、未列目标、环回地址、重定向到内网和 DNS 解析变化，确认拒绝结果、日志与恢复步骤。

## 卡片 7：文档库先验证状态机，再调召回

**证据状态：研究建议（发布阻断）。** `CLM-007/019` 当前未完成成功、失败、Stale 与恢复 fixture 的隔离复现。

**问题和适用条件。** RAG 无结果常被误判为 Prompt 或模型问题，实际可能是 Loader、切分、Embedding、维度、Upsert 或 Record Manager 的状态错误。

**证据与版本。** 目标服务有文档库状态码测试；官方资料把数据处理拆为多个阶段；开发者报告过 API 创建 Loader 后 UI 预览异常。[CLM-007][CLM-019]

**推荐做法。** 固定一个可人工判断的十条合成 FAQ，按“加载成功—切分可见—向量写入—检索命中—引用正确”逐层检查。只有基础状态机通过后才调整 chunk、top-k、metadata 过滤和 rerank。

**不适用情况。** 不使用文档库的直接提示流程无需 RAG 调优，但仍要管理上下文长度。

**成本和风险。** 多一步分层诊断，显著减少盲目重建索引和重复 Provider 费用。

**复现实验。** 注入一条唯一事实，分别制造空文档、错误维度、Stale 记录和 metadata 过滤过严四种失败，再按执行树定位最早异常节点。

## 卡片 8：所有外部副作用都要有幂等键和清理账本

**证据状态：经验建议（发布阻断）。** `CLM-023` 当前未完成目标版本外部副作用控制实验。

**问题和适用条件。** HTTP、Tool、MCP、Upsert 和工单更新可能产生费用或真实写入。失败重试若没有幂等控制，会重复创建工单、发送通知或写入向量。

**证据与版本。** 目标源码包含 Custom Tool、MCP 和文档库写入路径；官方资料明确这些节点可以调用外部系统。[CLM-023]

**推荐做法。** 实验对象使用唯一合成前缀，写入请求携带幂等键；ledger 记录对象 ID、基线指纹、调用次数、估算费用和删除结果。达到费用上限、出现未知写入或清理失败时立即停止。

**不适用情况。** 纯计算、无网络且无持久化的节点不需要外部清理，但仍要记录执行输入输出边界。

**成本和风险。** 需要额外的测试 API 和清理脚本；收益是重试可控、费用可审计、实验残留可发现。

**复现实验。** 对同一合成工单故意重放三次请求，确认最终只产生一个业务变更；随后执行清理并比对基线指纹。
