# API 密钥完整 SOP

## 目标

创建一把最小权限、可轮换、可撤销的 FlowAgentic API 密钥，并验证它只访问批准的流程和调用路径。

## 适用角色

管理员签发和撤销；开发者在服务端秘密存储中使用；流程搭建者确认密钥可访问的流程与副作用。

## 适用版本与功能状态

适用于 Flowise `3.1.3`、提交 `96f6ae46…` 的 API 密钥模块。管理 API Key、Flow API Key、Cookie 和 MCP Token 不是同一种认证材料。

## 前置条件与风险

- 明确调用方、来源网络、目标流程、允许动作、失效时间和负责人。
- 目标流程必须先完成副作用和费用审计；测试只使用合成数据。
- 密钥可能触发 Provider 费用或外部写入，必须与 Provider 预算和工具幂等门禁联动。

## 初始状态

从密钥列表确认无同名对象、无活动测试会话；准备一个只读健康调用和一个应被拒绝的越权调用。

## 操作步骤

1. 以“调用方—环境—用途”命名，设置最小权限和失效计划。
2. 创建密钥；若只显示一次，立即写入受控秘密管理工具，不复制到笔记或聊天。
3. 关联批准的最小流程，保存后复核关联关系。
4. 从服务端测试客户端发起合法请求，核对状态码、请求 ID、执行记录和费用。
5. 使用同一密钥请求未授权资源，确认得到 401/403 且无业务执行。
6. 轮换时新增第二把密钥，双轨验证后切换调用方，再撤销旧密钥。
7. 删除前停止调用方；删除后再次请求，确认旧密钥失效且没有缓存会话继续可用。

## 逐步检查点

- 创建时只在受控位置出现一次明文，站点、日志、截图、URL 均无 Key。
- 合法调用只命中批准流程；越权调用没有 Execution 或外部副作用。
- 轮换期间没有双重写入，旧密钥撤销后立即失败。

## 成功结果

批准调用成功、越权调用被拒绝、旧密钥已撤销；关联流程、调用方、费用和撤销证据均可追溯。

## 常见错误与诊断

- 401：检查 Header 格式、密钥状态和是否误用 Provider Key。
- 403：检查流程关联、工作空间和权限，不要扩大密钥权限绕过。
- 调用成功但无流式事件：区分 Prediction、Streaming 和客户端读取方式。
- 撤销后仍成功：检查代理缓存、旧 session、第二把密钥或错误环境。

## 回退与清理

切回上一已验证密钥只用于短时恢复；立即停止新请求，撤销失败批次密钥，删除合成执行和客户端临时配置，复核旧 Key 不再可用。

## 安全提示

浏览器前端不可持有长期管理密钥。禁止把密钥放入 URL、Embed HTML、公开 JavaScript、截图、CI 日志或仓库；泄露时先撤销再调查。

## 练习任务

为 FAQ Chatflow 创建一把训练密钥，完成合法 Prediction、未授权流程拒绝、轮换和旧密钥撤销验证。

## 验收清单

- [ ] 调用方、权限、流程、失效和负责人已登记。
- [ ] 合法请求成功，越权请求被拒绝且无执行。
- [ ] 轮换和撤销链路通过。
- [ ] 秘密扫描、费用账本和残留检查通过。

## 来源与验证

本 SOP 引用认证分层和副作用 Claim。API Key 的最终权限与关联界面必须在精确候选提交的同版本隔离培训环境按截图清单复验。
