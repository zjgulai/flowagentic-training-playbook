# 变量完整 SOP

## 目标

建立可追溯的静态变量与 Runtime 变量，验证 `$vars` 和请求级覆盖的最终取值，并防止客户端覆盖安全边界。

## 适用角色

流程搭建者设计变量合同，开发者约束 API 覆盖面，管理员负责环境级值和访问权限。

## 适用版本与功能状态

适用于 Flowise `3.1.3`、提交 `96f6ae46…` 的变量模块；覆盖优先级必须在同版本隔离培训环境重新验证。

## 前置条件与风险

- 为每个变量定义名称、类型、默认值、作用域、敏感等级和允许覆盖者。
- 准备一个只回显非敏感最终值的最小流程与三组对照输入。
- 变量不是秘密存储；禁止放入密码、Token、Cookie、内部连接串和个人信息。

## 初始状态

确认变量列表无同名对象，流程未缓存旧值，测试请求没有携带历史 `overrideConfig`。

## 操作步骤

1. 创建一个非敏感静态变量并填写明确默认值。
2. 创建一个 Runtime 变量，记录其必须由哪一调用方提供。
3. 在最小流程中通过 `$vars` 引用两者，保存并重新打开确认引用未丢失。
4. 不带覆盖运行一次，记录默认值结果。
5. 仅覆盖允许字段运行一次，记录请求值结果。
6. 尝试覆盖未允许字段，确认请求被拒绝或保持服务器值。
7. 修改默认值后新建 session 复测，区分运行级、session 级和持久配置。
8. 删除变量前查找引用；删除后验证流程给出明确错误而非使用不可见旧值。

## 逐步检查点

- 变量名稳定、类型一致、无秘密内容。
- 保存重开后 `$vars` 引用仍指向同一变量。
- 三组执行记录能区分默认值、合法覆盖和非法覆盖。
- 不同 session 没有意外共享 Runtime 值。

## 成功结果

变量来源和覆盖优先级可由执行记录重现；允许列表外的配置无法由客户端改变；删除不存在残留引用。

## 常见错误与诊断

- “变量未生效”：检查拼写、大小写、保存状态、节点表达式和覆盖层级。
- “不同请求串值”：核对 session、Flow State 与持久变量边界。
- “客户端能改端点”：立即收紧允许列表，检查 `overrideConfig` 和嵌入配置。
- “删除后仍有值”：清理缓存并以新 session 复测，不修改生产数据验证。

## 回退与清理

恢复上一已验证默认值，移除请求级覆盖，删除练习流程和合成变量；确认变量列表、执行记录和 session fixture 回到基线。

## 安全提示

允许客户端覆盖的字段越少越好。模型端点、内部 URL、系统指令、权限开关、工具写入模式和秘密引用不得开放覆盖。

## 练习任务

为“工单优先级阈值”建立默认值和 Runtime 覆盖，证明合法覆盖生效、非法模型端点覆盖被阻断、两个 session 相互隔离。

## 验收清单

- [ ] 变量合同含类型、默认值、作用域和敏感等级。
- [ ] 默认、合法覆盖、非法覆盖三组对照完成。
- [ ] session 隔离和执行记录可追溯。
- [ ] 练习对象与残留清零。

## 来源与验证

变量边界引用 `CLM-008/015/023`。覆盖优先级目前仍是待隔离环境验证的 Claim，正式发布门禁会拒绝未通过的本地复现。
