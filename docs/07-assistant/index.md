# 自定义助手

## 适用场景

当需求可以通过“模型＋系统指令＋知识库＋有限工具”表达，并且不需要复杂条件、循环或多阶段人工审批时，优先使用自定义助手。

## 创建 SOP

1. 新建助手并写清名称、业务目标、回答边界和所有者。
2. 选择培训环境中的模型凭据，设置可控参数和费用上限。
3. 编写指令：角色、任务、可用信息、禁止事项、输出格式和不知道时的行为。
4. 需要知识时绑定已完成 Upsert 的合成文档库；不要把“已创建”误当作“可检索”。
5. 仅添加完成权限、副作用和错误处理审查的工具。
6. 保存后刷新页面，确认配置持久化。
7. 在对话预览中验证正常问题、无答案问题、恶意指令和工具失败。
8. 发布 API 或配置前完成授权、限流、CORS/CSP 和秘密扫描。

## 关键检查点

- 文档库处于可检索状态，Embedding 与 Vector Store 配置一致。
- 工具描述清楚说明何时调用和何时不调用。
- 助手在缺少证据时会拒绝编造。
- 预览成功不代表 API、Embed 或其他调用方式已经验收。

## 弃用边界

OpenAI Assistant 相关旧能力按 `deprecated` 处理，迁移时先盘点线程、文件、工具和业务依赖，再用 Custom Assistant 或适合的流程对象重建。不要直接删除旧对象作为迁移手段。

正式截图等待 G1 后覆盖创建、模型、指令、知识库、工具、保存、预览和 API 配置状态。

## 目标

建立一个边界清晰、知识可检索、工具受控的自定义助手，并验证无答案、恶意输入和工具失败路径。

## 适用角色

新手负责对话验证，搭建者配置模型／指令／知识库／工具，管理员负责凭据、费用和 API 暴露。

## 适用版本与功能状态

Custom Assistant 在基线为 `production-enabled`；OpenAI Assistant 旧能力按 `deprecated` 迁移附录处理。

## 前置条件与风险

需要已 Upsert 且通过检索测试的合成文档库、受控模型凭据、经审查工具和费用上限。模型可能编造，工具可能写入。

## 初始状态

从助手列表开始，确认无同名对象，目标文档库状态可检索，工具和凭据只属于培训环境。

## 操作步骤

新建命名 → 选模型 → 写指令和拒答边界 → 绑定文档库 → 添加最小工具 → 保存重开 → 预览四类问题 → 检查执行 → 配置 API。

## 逐步检查点

指令包含角色、任务、来源和不知道时行为；文档库有检索证据；工具说明明确何时不调用；预览和 API 分开验收。

## 成功结果

有答案问题引用合成来源，无答案问题明确拒答，恶意指令不突破边界，工具失败给出可恢复错误且不重复写入。

## 常见错误与诊断

无知识结果先检查 Upsert 和 Playground；工具误调用改进描述和 Schema；预览成功但 API 失败时检查认证、CORS/CSP、流式读取和限流。

## 回退与清理

移除新工具和文档库引用，恢复上一指令版本；删除本次助手、执行和外部对象，保留共享文档库只读。

## 安全提示

助手指令不是访问控制。敏感数据必须在检索与工具层限制；API 公开前验证认证、最小化返回、限流和秘密扫描。

## 练习任务

创建工单 FAQ 助手，验证有答案、无答案、提示注入和工具超时四组问题，并给出清理回执。

## 验收清单

- [ ] 模型、指令、知识库和工具边界明确。
- [ ] 四类测试与执行记录通过。
- [ ] API 风险和旧能力迁移状态已标注。

## 来源与验证

文档库状态与 Upsert 前置引用 `CLM-007/019`，副作用引用 `CLM-023`；正式截图和运行链等待隔离环境。
